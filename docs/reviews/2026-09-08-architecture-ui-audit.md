# 2026-09-08 架构检查、隐藏缺陷修复与界面改进

范围仅为音云 `yinyun-lxserver`，基线为 `baea3f3`。Songloft 是外部服务；本轮不修改其代码、容器、配置、音乐或歌单。没有执行数据迁移、删除用户数据或新建生产备份。

## 架构判断

后端是单实例 Node.js 服务：`server.ts` 装配服务与兼容路由，`apiV1.ts` 和 `subsonic.ts` 提供协议接口；认证、跨用户同步、歌曲匹配、外部库和原子存储已有独立服务。前端采用经典脚本，播放器与管理端共享曲库联动模块，但拥有不同的页面、主题和 PWA scope。

本轮问题主要集中在前端状态边界：本地媒体和在线解析没有完全分开、缓存键未充分隔离、异步响应与当前账户/当前视图没有绑定。直接重写导航或后端存储会扩大风险，因此沿现有模块修复，不迁移数据格式。

## 确认并修复的问题

| 问题 | 原因与修复 |
| --- | --- |
| 本地歌曲失败后长时间重试 | 直接本地文件分支排除了 `isRetry`，导致重试进入在线解析。保持本地路由，媒体失败只重新验证并重试一次，再明确停止报错；在线歌曲的缓存失败仍可以回退在线解析。 |
| 跨用户/平台复用播放链接 | 持久 URL 缓存只含歌曲 ID 和音质；预读只含 ID。统一加入账户、平台、音质、曲库所有者和文件位置。异步预读在账户变化后丢弃，退出时停止预读音频。旧缓存不再读取。 |
| 不可信媒体地址可能收到登录令牌 | 本地标记不足以证明 URL 可信。附加令牌前校验实际 origin 和明确的本站媒体路径，排除第三方和协议相对地址。 |
| 探活可能额外下载整首歌 | 部分服务器忽略 Range，原代码只检查响应头而不取消 body。检查后取消响应流，成功/失败都清理超时和 AbortController。 |
| HEAD 播放检测返回 401 | 文件服务支持 HEAD，但查询令牌白名单只有 GET。仅对缓存文件只读路径开放同等 HEAD 认证；未授权及管理接口仍拒绝。 |
| 联动刷新重置同步目标 | 重建下拉框后丢失选项。读取响应完成时的最新选择，目标仍存在时保留，合法的 0 首不使用其他字段错误回退。 |
| 旧歌单响应覆盖新歌单 | 打开请求没有版本标记。加入请求序号及账户凭据对照；选择下拉框不再提前改写正在显示的记录 ID。 |
| 刷新跳页、勾选丢失 | 每次重匹配无条件清空选择并 `scrollIntoView`。后台刷新不滚动，相同歌曲身份保留选择，来源或顺序变化时剔除无效选择；内容相同时保留行 DOM。 |
| 管理员临时连接串入播放器 | 可能把播放器用户名与管理页 sessionStorage 中另一用户的令牌混合。播放器只使用自己的成对凭据，管理端临时连接仍独立。 |
| 已删除歌单仍显示在导入历史 | 空歌单列表被当成“尚未加载”。显式区分未加载与成功空列表。 |
| 离开联动页面后仍轮询 | 停止标记被尚未移除的 CSS active 类覆盖，异步激活完成后又启动轮询。显式停止优先，激活请求用序号防止过期启动，退出清理会话和试听。 |
| 播放器底部透出列表文字 | `t-bg-panel/90` 不是已生成的 Tailwind 样式。为播放器底栏设置明确的主题背景色。 |

## UI 调整

- 桌面联动保留表格，移除 520px 的内部纵向滚动限制。
- 768px 及以下使用连续滚动的歌曲卡片；音云与 Songloft 的匹配状态并列展示，长标题换行。
- 手机统计区改为紧凑的三列排列，扩大试听按钮触摸区域，输入框使用 16px 字号避免 iOS 聚焦放大。
- 两个页面统一区分“Songloft 歌单实际歌曲数”和“索引匹配数”，不再使用相同标签混淆不同指标。
- 补充键盘焦点、加载状态、复选框标签、返回及播放全部按钮的可访问名称。
- 共用 `integration-responsive.css`，同时纳入两个 PWA 的预缓存；播放器只对白名单中的共享 CSS/JS 提供离线访问，不接管管理 API。

## 验证方法及边界

新增测试执行真实前端函数（Node VM），包括延迟/乱序响应、账户切换、目标保持、勾选保持、旧记录删除、本地重试与令牌 URL 边界；不是仅检查源文件是否出现某个字符串。媒体测试运行真实 HTTP 服务，验证 HEAD、206、416 和未授权响应。

浏览器使用实际工作树 HTML/CSS/JS 和隔离的合成歌单。覆盖 320、360、375、390、393、412、430、768、1280px，浅色/深色主题、页面级滚动、刷新不改目标和不重置勾选。自动化视口不等于 iPhone/Android 真机验收，模拟 Songloft 响应也不等于真实 Songloft 联调。

本地 Firefox 浏览器已验证：从具体歌单点播真实可解码的 30 秒测试 WAV，媒体时间推进超过 6 秒、无媒体错误；应用返回后立即重进、等待 61 秒重进以及浏览器后退均成功。返回期间歌单网格子节点变更数为 0，保留原卡片 DOM，12 张歌单卡片均仍可操作。测试音频仅用于验证播放链，不是真实用户歌曲。

生产发布需要另行核对 Git 提交、Actions 结果、镜像 digest、路由器容器 revision 和真实播放。若路由器 SSH 不可达，必须明确报告未部署，不得用公网首页能打开替代生产验收。

## 后续风险

`server.ts`、`apiV1.ts`、`fileCache.ts`、播放器主脚本仍偏大；部分旧测试是源码断言，不能代替行为验证。此次是有边界的风险扫描，不代表已排除所有潜在缺陷。涉及持久化、Songloft 写入和跨用户权限的进一步调整应继续用故障注入及真实、可控的业务验证独立发布。
