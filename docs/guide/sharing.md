# 歌单与音源分享

V1 支持三类不同的数据流：用户之间的歌单邀请、管理员向其他用户提供自定义音源，以及管理员直接执行的跨用户独立副本同步。

## 歌单分享开关

每个用户都必须在 **设置 -> 歌单分享** 中主动开启分享。开启表示：

- 允许向其他用户发送自己的歌单。
- 允许接收其他用户发来的歌单邀请。

如果接收方未开启，发送时会提示对方不接受分享。管理员和普通用户遵循相同规则。

## 分享歌单

1. 在左侧自建歌单旁点击分享按钮。
2. 输入对方用户名，用户名不区分大小写。
3. 服务器验证双方设置后创建邀请。
4. 接收方登录时看到待处理弹窗，也可从设置中打开待处理列表。
5. 接收方选择接受或拒绝。

接受后，服务器把歌单内容复制到接收方的收藏歌单。拒绝则不写入。之后双方歌单彼此独立，一方修改不会实时改变另一方副本。

## 文件空间占用

分享行为只复制歌单记录，不复制音频文件，因此分享本身不会占用双倍音乐空间。所有已登录用户都能只读访问其他用户 `/music/<用户名>` 的长期音乐，所以接收方可以直接播放共享本地歌曲；对方的临时 `/cache` 不可见。

如果接收方之后选择“下载到服务器”，V1 会写入接收方自己的 `/music/<用户名>`，通常会形成另一份物理文件并额外占用空间。V1 没有跨用户内容寻址去重仓库。

## 可分享歌曲的条件

有平台 ID 的歌曲可由接收方通过自己的音源在线解析。已经位于任一用户长期 `/music` 目录的本地歌曲即使没有平台 ID，也可携带稳定的本地 ID、文件路径和所有者加入歌单，并由其他已登录用户只读播放；仅存在于临时 `/cache` 的未绑定歌曲不能作为共享本地歌加入歌单。

## 管理员跨用户同步

管理员可在 `/admin` 直接把某个用户的歌单追加或覆盖到另一个用户，也可把某个用户拥有的音源复制给多个用户。这是运维级复制，不走邀请和接收确认；目标收到的是独立副本。歌单覆盖遇到空源和非空目标时始终拒绝；同一目标歌单的写入按目标互斥，失败会恢复原歌曲并重新生成恢复快照。音源覆盖只影响明确选择的同 ID 源。

## 音源分享

音源分享由管理员执行：

1. 管理员登录 Web 播放器并打开自定义源管理。
2. 在自己的源卡片点击分享。
3. 选择全部用户或指定用户后保存。
4. 接收用户重新登录或刷新源列表后即可使用。

管理员可以随时调整接收用户或撤销分享。共享的是完整脚本能力和使用权，不会向普通用户透露管理后台密码。

共享音源会展示脚本支持的全部平台。管理员对自己音源的平台选择不会传递给接收者；每个接收者可以独立勾选自己要使用的平台，且不能修改原脚本。平台选择会同时约束 Web 播放、下载、自动换源和 Subsonic 播放。

## 权限边界

- 用户只能发送自己拥有的歌单。
- 接收方必须明确接受，发送方不能直接写入对方歌单。
- 普通用户不能修改管理员共享的源。
- 普通用户可以独立调整共享源的平台开关，不会影响管理员或其他用户。
- 分享不会绕过平台版权、会员权限或音源脚本本身的限制。
- 共享本地音乐为只读访问：非所有者不能删除、重命名、更新元数据或清理该文件。
